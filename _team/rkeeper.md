# 🔴 Перехід з R-Keeper (Restera) — план

Джерело: `../reports/Перехід з RKeeper.md` (дослідження 22.10.2026). Частина плану «Одна система» (`одна-система.md`, таблиця адаптерів, рядок 5).
Головне правило: дані забираємо, **поки в клієнта працює сервер RK7** (файли UDB закриті). Продаж — «рятування даних»: безкоштовне вивантаження до рішення про перехід.

## Де лежать дані R-Keeper → куди в нас
| R-Keeper | Як забрати | Наш вид (`mig.js`) |
|---|---|---|
| Меню, категорії, ціни (RK7 `MENUITEMS`, `CATEGLIST`) | RK7_dbf «меню» (.dbf) або XML `GetRefData` (.xml) | `menu` |
| Схеми модифікаторів (`MODISCHEMES`, `MODIGROUPS`, `MODIFIERS`) | XML | ⬜ R3 — модифікаторів у нас ще немає |
| Типи цін (`PRICETYPES`) | XML / RK7_dbf (лише один) | ⬜ R4 |
| Персонал (`EMPLOYEES`) | RK7_dbf / XML | `staff` (PIN не переноситься) |
| Калькуляційні карти, напівфабрикати | StoreHouse 5: Excel або `sh5exec` | `cards` |
| Товари й залишки по складах | StoreHouse 5: звіт залишків → Excel | `ing` |
| Постачальники (кореспонденти) | StoreHouse 5 → Excel | `sup` |
| Гості, картки, бонуси, депозити | CRM-звіт балансів на момент відсічки | `cli` (+ R2: картка, група, депозит) |
| Сертифікати | CRM / облік адміністратора | `cert` |
| Історія чеків | SQL-копія сервера звітів (UseSQL=1) або RK7_dbf «чеки» | ⬜ R5 архів |

## Етапи
- **R0 — швидкі правки (✅ 22.10, керівник):** `rkeeper` у `SYS`; майстер читає .dbf (RK7_dbf) і .xml (довідники XML-інтерфейсу); підказки колонок R-Keeper; інструкція «що вивантажити» для R-Keeper; меню — новий стовпець «Розмір» (варіанти), повторний імпорт **не стирає** розміри; персонал з R-Keeper: «менеджер» ≠ адмін; індекс сертифікатів 500 → 5000; баг: «Персонал» і «Броні» в майстрі падали (немає підказок колонок).
- **R1 — перевірка на живому вивантаженні:** взяти реальні файли першого клієнта (RK7_dbf, XML, Excel StoreHouse) → підправити підказки/мапінг. До цього не обіцяти «все за день».
- **R2 — гроші гостей (✅ 22.10, керівник):** `cli` — «Номер картки» (`cli.card`, пошук гостя за карткою на касі), «Група / рівень» (→ рівень лояльності за назвою; нема такого — попередження + нотатка), «Депозит, ₴» → сертифікат гостя `DEP-<телефон>` (`paid:'mig'`): гаситься як сертифікат на касі й у боті (паритет уже був), видно в картці гостя (каса + бот). Не дохід у нас — гроші отримані в старій системі; мінусовий депозит (борг) — не переносимо. **Відкрите:** поповнення депозиту вже в ATOM (новий аванс) — лише після рішення бухгалтера.
- **R1-збирач (бета, 22.10):** `rk/atom-rk7-export.ps1` — кнопка в майстрі (система R-Keeper): XML-інтерфейс `GetRefData` (CATEGLIST, MENUITEMS, EMPLOYEES, + сирі PRICETYPES/MODI*/DISCOUNTS для R3/R4) і `GetOrderMenu` (ціни, копійки ÷100) → menu.csv, staff.csv + *.xml. Не перевірено на живому RK7 (PowerShell тут немає) — перевірити в R1: назви атрибутів (`MainParentIdent`/`CategPath`), ціни в копійках.
- **R3 — модифікатори** — дизайн нижче, ⏸ чекає «так» власника.
- **R4 — типи цін** — дизайн нижче, ⏸ чекає «так» власника.
- **R5 — архів продажів** (лише читання, R2-сховище): чеки, оплати, зміни з SQL-копії або DBF — порівняння рік до року.
- **R6 — решта:** комбо; податкова група / акциз на позиції (звʼязок з е-маркою); техкарти за кодом + напівфабрикати; > 2 складів; локальний збирач для Windows (XML `GetRefList`→`GetRefData` + SH5 `sh5exec` → файли в майстер, як програма для 1С).

## Не код
- Власник: вручну перевірити реєстр санкцій РНБО («КОМПАНИЯ ЮСИЭС», «ФУДПЛЕКС», «КБЦП СПЕКТР») перед публічними заявами.
- Маркетинг: оффер «рятування даних з R-Keeper» + чек-лист 14 запитів клієнту (звіт, розділ «Чекліст»).
- Бухгалтер: облік депозитів, прострочених сертифікатів, бонусів.

## Дизайн R3 — модифікатори (чекає рішення)
**Що це:** «Капучино» → обовʼязково молоко (звичайне / рослинне +15 ₴), за бажанням сироп (0–2, по +10 ₴); «Стейк» → прожарка (1 з 3, безкоштовно).
**Рекомендую — модифікатор = окремий рядок чека** (рядки в нас уже `«N× назва — сума»`, `LINE`):
- Меню: `menu.mods = [{ id, name: 'Молоко', min: 1, max: 1, items: [{ n: 'рослинне', p: 15 }] }]`, у страви `it.mods = ['milk', 'syrup']`. Кабінет → Меню: вкладка «🧩 Модифікатори» + галочки на страві.
- Каса: тап на страву з модифікаторами → вікно вибору (обовʼязкові не пропустити); у замовленні рядок `1× Капучино › рослинне — 15` під стравою. Бот персоналу — те саме кнопками (паритет). Меню гостя (QR) — той самий вибір.
- Кухня: модифікатори з відступом під стравою; безкоштовні (прожарка) — теж, щоб кухар бачив.
- Склад: рядок-модифікатор має свою техкарту за назвою («Капучино › рослинне» −200 мл молока + 200 мл рослинного) — механізм списання не міняємо.
- ПРРО: платні — окремі позиції чека; безкоштовні — не фіскалізуються (сума 0).
- Звіти: модифікатори видно окремо («скільки рослинного молока продали»).
- R-Keeper: `MODISCHEMES`/`MODIGROUPS`/`MODIFIERS` (уже зберігає збирач) → новий вид `mods` у `mig.js`.
**Альтернатива** (простіше, гірше): модифікатор = текстовий коментар до страви без ціни й списання. Підходить лише для «без цибулі».
**Обсяг:** ~3–4 дні (каса, бот, меню гостя, кухня, кабінет, міграція, тести).

## Дизайн R4 — типи цін (чекає рішення)
**Що це:** одна страва — різна ціна в залі / з собою / на доставці (у R-Keeper `PRICETYPES`; банкет — рідко).
**Рекомендую:** у страви необовʼязкове `it.pr = { pick: 95, del: 110 }`; немає — діє звичайна ціна. Тип береться з рахунку: стіл → зал, 🥡 → `pick`, 🛵 → `del` (віртуальні столи доставки вже є). Розміри (`variants`) — `v.pr` так само.
- Кабінет → Меню: дві необовʼязкові колонки «Ціна з собою», «Ціна доставки»; майстер переходу — ті самі поля.
- Каса / бот / сайт доставки — показують і рахують ціну свого типу; перенос страви між столом і доставкою — перерахунок.
- Банкет — не робимо (банкет у нас — бронь з передоплатою; ціни ті самі).
**Обсяг:** ~1–2 дні.
