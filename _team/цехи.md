# 🍳 Цехи кухні (дизайн, без коду) — чернетка 2026-10-17

## Що є зараз
- Позиції меню належать **категорії**; `groupOf(cat)` (ops.js) відносить категорію до однієї з 4 груп: `kitchen | bar | hookah | other` (на кожен заклад — свій `cur().cg`).
- Друк (print.js): кожен принтер має список груп `g`; рядок замовлення йде на перший принтер, чия група збігається, інакше на «kitchen», інакше на перший.
- Екран кухні `/k` (kitchen.js, ES5) один, показує всі події; статус «готово» — на рівні замовлення/позиції без поділу по групах.

Тобто «цех» = група, але лише для друку. Екрана й статусу готовності по цехах немає.

## Мета
Заклад описує свої **цехи** (напр. 🔥 Гарячий, 🥗 Холодний, 🍹 Бар, 💨 Кальян, 🍰 Десерти). Кожна позиція йде у свій цех: свій екран, свій принтер, своя готовність. Офіціант бачить, що готово по цехах.

## Модель даних (міграція, стара не змінюється)
- `cfg:stations` = `[{ id, name, emoji, printer?: <id принтера>, pin?: ... , order }]`. За замовчуванням створюються з 4 наявних груп (kitchen→«Кухня», bar, hookah, other) — **зворотна сумісність**: без налаштування все працює як зараз.
- Прив'язка категорій: `station` на категорії меню (поле `st` у категорії); необов'язкове перевизначення на позиції (`item.st`) — напр. «салат» у холодний, «борщ» у гарячий в одній категорії «Їжа».
- Рядок замовлення отримує `st` (id цеху) **на момент відправки на кухню** (знімок, щоб зміна меню не ламала відкриті чеки). Старі рядки без `st` → `groupOf`.
- Готовність: `ready` з рядка/замовлення переходить на рівень **(замовлення × цех)**: `order.rd = { <stationId>: ts }`. Замовлення «готове цілком», коли готові всі цехи, де є позиції.

## Маршрутизація
1. Відправка на кухню: рядки групуються по цехах.
2. Кожен цех отримує **свій квиток** (друк на принтер цеху; fallback — принтер групи, потім «kitchen», потім перший — як зараз).
3. Подія на екран: кожен цех бачить лише свої позиції + номер столу/замовлення + позначку «інші цехи: 🍹 готово / 🔥 готується» (щоб тримати подачу разом).
4. Позиції з курсом/затримкою (`course`) — як зараз, але в межах цеху.

## Екрани
- `/k?st=<id>` (або вибір цеху після входу кухаря); роль `cook` може мати доступ до одного/кількох цехів (поле `stations` в профілі працівника). Адмін бачить усі. Без вибору — об'єднаний екран (як зараз).
- Кнопка «✅ Готово» на позиції/замовленні цеху → подія `ready` з `st`; офіціанту в боті/касі: «🍹 Бар: готово» окремо від «🔥 Гарячий: готується».
- Кухонний iPad (ES5): лише додати параметр цеху й фільтр у `feed()`; без нових залежностей.

## Налаштування (каса ⚙️ + кабінет власника)
- Розділ «🍳 Цехи»: список цехів, перетягування, принтер цеху (з наявних `st`), прив'язка категорій галочками.
- Паритет каса ⇄ бот: показ статусів по цехах в обох; перевизначення цеху позиції — у меню-редакторі.

## Ризики й рішення
- Один принтер на кілька цехів — дозволено (квитки друкуються окремо, з заголовком цеху).
- Позиція без цеху → цех за замовчуванням (перший або «Кухня»); ніколи не губиться.
- Склад/собівартість не залежать від цехів (списання лишається при продажу/готовності як зараз).
- Мультизаклад: усе в `cfg:` закладу, жодних глобальних змінних.
