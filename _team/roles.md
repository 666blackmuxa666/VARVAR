# 🔑 Ролі й права з галочками — ПЛАН (код не чіпаємо до ок 👑) — 2026-10-17

## Що є зараз
- 4 жорсткі ролі: `admin | waiter | cook | courier` (`staff.role`).
- Права = `me.role === 'admin'`. У `pos.js`: ~60 перевірок `if (!admin) return needAdmin()` (блок «admin-only» з `if (!admin)` на ~рядку 252 + одиничні в `case`). Ще: `stock.js`, `tasks.js`, `kitbot.js`, `bot.js` (`isAdmin`), `ops.js` (PIN-правило).
- Каса ховає вкладки/кнопки за `S.me.role`; бот показує `ADMIN_KB` лише адміну.
- Наслідок: «старший офіціант» або «менеджер зміни» — або повний адмін (небезпечно: видалення, ЗП, ціни), або нічого.

## Мета
Власник у картці працівника ставить **галочки прав**. Ролі лишаються як **шаблони** (стартовий набір), але конкретні права редагуються.

## Модель даних (без міграції формату)
- `staff[i].perm = { <ключ>: 1 | 0 }` — лише відхилення від шаблону ролі. Немає поля → поведінка як зараз (**зворотна сумісність, відкат безпечний**).
- Шаблони: `ROLE_PERMS = { admin: усі, waiter: [...], cook: [...], courier: [...] }` у новому `worker/src/perm.js`.
- `can(me, key)` = `me.perm?.[key] ?? ROLE_PERMS[me.role].has(key)`. **Admin завжди має все** і не може позбавити себе `staff` та `perm` (захист від самоблокування; завжди лишається ≥1 повний адмін).
- Права читаються з сесії при кожному запиті (не кешуються в токені) → зміна діє одразу.

## Каталог прав (первинний, ~16 груп)
| ключ | що дозволяє | ops, що прив'язуємо |
|---|---|---|
| `void` | видалення позицій/рахунків, повернення | `voidBack`, `closedDel`, `tableBack` |
| `discount` | знижки > X% | `discount` |
| `edit_closed` | правка/повторне відкриття закритих | `closedEdit`, `closedReopen`, `closedBack` |
| `cash` | внесення/вилучення, витрати, зміна/Z | `expense*`, `shift*`, Z |
| `reports` | звіти продажів, ЗП-огляд, експорт бухгалтеру | `reportRange`, `acctExport` |
| `stock` | склад: прихід, списання, інвентаризація | `st*`, `loss*` |
| `stock_cost` | бачити собівартість/маржу | `costReport` |
| `menu` | редагувати меню/ціни/цехи | `menuImport`, `catSet`, `stSet`… |
| `staff` | персонал, PIN, ЗП | `staff*`, `payroll` |
| `pay_view` | бачити ЗП інших | `payroll` |
| `print` | налаштування друку | `printRoute`, `rcptSet`, `tabReg`… |
| `delivery` | диспетчер доставки, кур'єри | `cour*` |
| `books` | броні/сертифікати/черга | |
| `loyalty` | акції, рівні, гості | |
| `tax` | податковий календар | `tax*` |
| `settings` | решта налаштувань, інтеграції | `adminRest` |

Принцип: **операція → один ключ** у таблиці `OP_PERM` (одна карта замість розкиданих `if (!admin)`); невідомий op → як зараз «лише admin» (безпечний дефолт).

## Етапи (кожен окремим комітом, тести між ними)
1. **Каркас без зміни поведінки:** `perm.js` (`ROLE_PERMS`, `can`, `OP_PERM`), у `pos.js` обгортка `needPerm(key)`; **шаблони = нинішнім ролям**, тож усі наявні тести зелені без змін. *(торкається ядра `pos.js` → потрібен ваш ок)*
2. **Заміна `if (!admin)` на `needPerm(...)`** по блоках (хвилями: каса-гроші → склад → меню/друк → персонал). Після кожної хвилі — API-тести.
3. **Сервер: `staffPerm` op** (лише `staff`-право): валідація ключів, захист «останнього адміна», запис у `alog`; `me` в `login`/`session` повертає `perm` (повний розрахований набір).
4. **Каса:** вкладки/кнопки за `can('…')` (`S.me.perm`); картка працівника: блок «🔑 Права» — галочки, згруповані; кнопка «Скинути до шаблону ролі». Стиль `.switch`.
5. **Бот персоналу (паритет):** клавіатура з урахуванням прав (`🔐 Лише для адміністратора` → перевірка `can`); у картці працівника в боті — перемикачі груп прав.
6. **Кабінет власника:** та сама картка (owner-venue).
7. **Тести:** кроки selftest: офіціант без прав → 403; видали право `void` → `voidBack` 403, дай → 200; не можна зняти `staff` у останнього адміна; старий працівник без `perm` працює як раніше. UI: галочки на 375/1280.

## Ризики
- **Безпека:** пропущений op лишиться «admin only» (безпечно), але пропущена **перевірка в боті/kitbot/tasks** може дати зайве — тому аудит усіх `role === 'admin'` (grep) у плані кроку 2.
- **PIN-правило:** хто має право `staff`/`cash`+, має 6-цифровий PIN? Пропозиція: PIN ≥6 для будь-кого з «чутливими» правами (`void, staff, settings, reports`) — рішення 👑/власника.
- **Мультизаклад:** `perm` — у `staff` закладу, глобальних змінних немає.
- **Обсяг:** ~2–3 дні (каркас 0.5, заміни 1, UI каса+бот+кабінет 1, тести 0.5).
