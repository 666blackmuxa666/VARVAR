# 🧪 Тестування (автотести)

## Що це
`tools/selftest.mjs` — постійний набір автотестів, одна команда. Без залежностей (Node 18+; для інтерфейсу — Node 22+ з вбудованим `WebSocket` і встановлений Google Chrome). Продуктовий код не змінює. Працює **лише** проти локального worker-test (інший `API` скрипт відмовиться запускати).

## Як запустити
1. Оновити тестову копію сервера: `rsync -a worker/src/ ../.varvar-test/worker/src/`
2. Запустити launch-конфіги **`worker-test`** (порт 8787) і **`site`** (порт 8000). Конфіг `worker` **не запускати** — там справжній Telegram.
3. `node tools/selftest.mjs`
   - `--api-only` — лише API (швидко, ~10 с); `--ui-only` — лише інтерфейс.
   - Змінні: `API=…` (типово `http://localhost:8787`), `SITE=…` (типово `http://localhost:8000`), `CHROME=/шлях/до/chrome`.
4. Код виходу: 0 — усе ✅, 1 — є ❌ (список у кінці звіту).

## Що перевіряє
**API**
- Реєстрація кодами тестової бази: адмін 1119, офіціант 1112, кухар 1113, кур'єр 1114 (імена `QA <роль> <прогін>`, наприкінці видаляються через `staffDel`).
- Стіл: офіціант замовляє страву + напій → сума з меню → на кухні картка лише зі стравою → `kStart`/`kDone` → `close` готівкою → стіл зник, є в `closed`.
- Доставка: `POST /api/go` (Д‑N) → адмін `accept` (go.st=acc) → кур'єр `courAct take/road/done cash` → чек закрито, `/api/orders` = done, `courMe` показує готівку.
- Скасування доставки в касі: (1) `/api/go` → `accept` → `kStart` → `delete` стола 10xx → `/api/orders` g=`rej`; (2) `/api/go` → `accept` → `remove` кожної страви → рахунок зник, g=`rej`; (3) той самий пристрій знову робить `/api/go` → 200.
- Бронь: `POST /api/book` (+3 дні) → `bkSet ok` → `bkEdit` дата +100 днів → `bkList` знаходить на новій даті й не на старій → `GET /api/book?id`.
- 🎁 Лояльність (`promo.js`): ручний рівень QA −10% → телефон на столі → знижка рівня сама (`promo`, `pay2`); ручна 15% → рівень не складається; закриття → `closed.promo`, історія клієнта; щасливі години на поточну годину → знижка без телефону, інший день тижня → не діє; `/api/promo` (самовивіз так, доставка ні); `/api/go` рахує акцію сам; `loyRep`; `loyCli` фільтр; офіціант 403 на `loyRule/loyRep/loyLevel/loyOff`. Чужі акції на час тесту вимикаються й потім повертаються.
- Права: кур'єр/кухар/офіціант отримують 403 на чужі op (close, shift, order, bkList, skData, goSt, staff, delete, zpGrid, courList); без токена — 401.

**Інтерфейс** (безголовий Chrome через CDP, `pos.html?api=…`)
- Для ролей адмін / офіціант / кухар / кур'єр на ширинах 375 / 880 / 1280: кожна кнопка розділу (`data-a="view"`) і кожна вкладка в ньому (`cashTab, rTab, setTab, skTab, zpTab, crTab`) + підвкладки `loyTab` (🎁 Лояльність).
- ❌ якщо: помилки в консолі/винятки, порожній `#main`, вміст вилазить за `.card` / `.kv` / `.kpi` (поза блоками з горизонтальним скролом), горизонтальний скрол сторінки.

## Тонкі місця
- Тест створює на тестовій базі закриті рахунки, доставки (Д‑N), броні й 1 стіл (стіл 1 для UI) — це нормально для worker-test.
- Доставка шлеться з `when: '12:00'` — щоб не залежати від години роботи.
- Антиспам `/api/go` і `/api/book` — 3 за 10 хв / год з пристрою; скрипт щоразу бере новий `device`.
