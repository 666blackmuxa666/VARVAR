# 🧾 План: фіскалізація (ПРРО) + термінали + єАкциз для ATOM

Статус: **етап 2 зроблено (2026-10-18)** — `worker/src/fiscal.js`, тест на «Все за 500» (atom-demo). VARVAR працює зі своїм РРО — не чіпаємо (fisOn = false для varvar).
Мета: продаж ATOM іншим закладам «під ключ» з фіскалізацією.

## 1. Юридичне (перевірити з бухгалтером ДО розробки)
- Хто зобов'язаний: ФОП 2–4 гр., ТОВ. Що з ФОП 1 гр. / без РРО.
- Округлення готівки, чайові (не в чек / окремий рядок?), сервісний збір.
- Алкоголь/тютюн: ліцензія, коди УКТЗЕД, акциз 5% з роздрібу, ПДВ-групи.
- **єАкциз для продажу на розлив**: коли сканувати марку (при відкритті пляшки чи в кожному чеку?) — ❓ уточнити чинні правила.
- Онлайн-оплата на сайті (LiqPay/mono): коли і хто видає чек.
- Готівка в кур'єра: чек видає кур'єр (мобільний ПРРО) чи заклад заздалегідь.
- Збереження даних, відповідальність ATOM vs закладу (договір/оферта).

## 2. Архітектура
- **Шар-провайдер** `worker/src/fiscal/`: єдиний інтерфейс `openShift / sale / refund / serviceIn / serviceOut / xReport / zReport`.
  Реалізації: `checkbox` (перший), далі `vchasno`, потім **свій ПРРО**. Заклад обирає в кабінеті.
- Налаштування закладу: ключ ліцензії каси, касири — лише `secret`/шифровано в БД, персонал не бачить.
- Касир у Checkbox: один на заклад чи на кожного працівника (PIN) — ❓ вибрати.
- Статус чека в замовленні: `не потрібен / в черзі / фіскалізовано (№, QR) / помилка`.
- Черга: якщо провайдер недоступний — чек у черзі, досилання без опитування (при наступній дії/зміні).
- Економія запитів: 1 запит на чек; статус — webhook провайдера, якщо є, інакше одна відкладена перевірка.

## 3. Операції каси ↔ фіскальні
| Наше | Фіскальне |
|---|---|
| Оплата столу / доставки | чек продажу (готівка / картка / змішана / розділений рахунок = кілька чеків) |
| Знижки, акції, лояльність | знижка в рядку / на чек |
| Повернення страви після оплати | чек повернення (повний/частковий) |
| Скасування до оплати | нічого (лише наш журнал) |
| Рух грошей: внесення/видача, інкасація | службове внесення/видача |
| Відкриття зміни | відкриття фіскальної зміни (авто при першому чеку) |
| Z-звіт | фіскальний Z + звірка сум; авто-закриття, якщо забули (ліміт 24 год) |
| Оплата на сайті | чек з типом безготівкова/інтернет |

## 4. Безготівковий термінал
- **Етап A (простий):** окремий термінал, офіціант вводить суму сам, у касі «💳 Оплачено» → чек `CASHLESS`.
- **Етап B (інтегрований):** сума йде на термінал через локальний агент (як принтер-агент `printer/`), повертає RRN, auth code, маску картки → у чек.
  Банки: ПриватБанк, Ощад, mono, Райффайзен — протокол від еквайра. Почати з банку першого покупця.
- **Етап C:** SoftPOS (оплата на телефон офіціанта/кур'єра) — ❓ дослідити.
- Захист: перевірка, що сума на терміналі = сума чека; заборона «оплачено карткою» без підтвердження (налаштування).

## 5. Друк і електронний чек
- Фіскальний чек на нашому принтері: фіскальний №, QR на перевірку в ДПС, обов'язкові реквізити.
- Е-чек гостю: Telegram-бот / SMS / email / QR на екрані.
- Копія чека в історії замовлення.

## 6. Паритет бот ⇄ каса
- Бот: статус фіскалізації, повторна відправка чека, сповіщення про помилки й незакриту зміну, Z-підсумок.
- Курʼєр у боті: фіскалізація готівки при доставці (якщо юридично так).

## 7. Звіти й контроль
- Звірка: наші продажі vs фіскальні (розбіжність → ⚠️ власнику).
- Список «не фіскалізовано» з кнопкою повторити.
- Журнал фіскальних операцій (хто, коли, що).

## 8. Кабінет власника
- Майстер «Підключити касу»: вибір провайдера → ключі → тестовий чек → готово.
- Перемикач тест/бойовий режим.
- Підказки з курсу 🎓 («як отримати ключ у Checkbox»).

## 9. Тестування
- Тестовий сервер Checkbox + наш `worker-test`.
- Кейси: продаж, змішана оплата, розділ рахунку, знижка, повернення, внесення/видача, Z, обрив мережі, повтор, подвійне натискання (ідемпотентність!), акцизний товар.

## 10. Комерція
- Хто платить за Checkbox (заклад напряму / через нас), партнерська програма Checkbox — ❓.
- Свій ПРРО — коли закладів багато (економія + продаж як частина ATOM).

## 11. Етапи
1. Юридичні відповіді (розділ 1) + вибір відкритих питань.
2. Провайдер Checkbox на тестовому: продаж/повернення/зміна/службові.
3. Друк фіскального чека + е-чек + бот.
4. Звірка, черга, помилки.
5. Майстер у кабінеті → перший заклад-покупець (бойовий).
6. Інтегрований термінал під банк покупця.
7. єАкциз.
8. Свій ПРРО.

## 📌 Висновки (жовтень 2026)
- Фіскалізуються ВСІ оплати (готівка, картка, онлайн); без чека — лише переказ з банківського рахунку на рахунок закладу. ФОП 1 гр. — без ПРРО.

- Свій ПРРО окупається від ~50–100 закладів; до того — Checkbox (~200–400 грн/міс за касу, ❓перевірити).
