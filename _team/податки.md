# 🧾 Податки, ПРРО, бухгалтерія — дослідження (без коду)

Станом на 17.10.2026. Дослідження за відкритими джерелами, **офіційні тарифи й документацію не відкривали** — усе, що не з первинного джерела, позначено.
Позначки: ✅ підтверджено кількома джерелами · ⚠️ один/сторонній огляд · ❓ не знайдено · 🔎 звірити в постачальника/бухгалтера.
Персональних даних немає. У репо ПРРО в ATOM зараз **немає** (`_team/roadmap.md:33`: «[ ] ПРРО Checkbox»).

## 0. Головне (читати першим)
1. **⏰ Е-акциз стартує 01.11.2026** (перенесено з 01.01.2026; тест до 11.10, реєстрація користувачів 12–31.10) ⚠️ (новинний огляд, 🔎 звірити). Для закладів з алкоголем це найближча вимога. Штрихкод акцизної марки в чеку обов'язковий ще з 2022 ✅; штраф за чек без нього — 100% суми чека, повторно 150% ✅.
2. **Порядок: ПРРО → акциз у чеку → бухгалтерський експорт → податкові нагадування.** Пряме подання звітності в ДПС від ATOM — не робити (див. §3).
3. Нагадування про податки (ЄП, ЄСВ) — найдешевше й безпечне: календар у кабінеті власника, без КЕП і без доступу до грошей.

## 1. Інтеграція з бухгалтерськими програмами
| Програма | Що є | Що реально |
|---|---|---|
| **BAS (1С-платформа)** | Стандартний OData/REST платформи (доступ без зміни конфігурації) ⚠️; готові обробки обміну з M.E.Doc ⚠️ | Однобічно **ATOM → BAS**: денні продажі, оплати, списання. Через файл (CSV/XML) — без залежності від версії BAS |
| **M.E.Doc** | REST API лише в мережевому варіанті та з окремою ліцензією «Інтеграція з обліковими системами» ✅ | Передавати документи (накладні, акти) можна, але **ціна й вимоги ліцензії — у клієнта** 🔎. Не для старту |
| **Дебет Плюс та інші** | ❓ відкритого API не знайдено | Лише файловий імпорт, якщо програма його має 🔎 |
Гроші/вартість: BAS — ліцензія й супровід у бухгалтера клієнта; ATOM нічого не платить. Для M.E.Doc — ліцензія API (ціна ❓).
**Конкуренти:** Poster і Syrve мають експорт звітів і публічний API для партнерів ⚠️; прямих «кнопок» у BAS/M.E.Doc у відкритих джерелах не побачили ❓. Тобто файловий експорт — це паритет, не відставання.
**Рекомендація:** фаза 1 — «📤 Експорт для бухгалтера»: дні/зміни, виручка за формою оплати, ПДВ/без ПДВ, чайові, повернення, списання, закупівлі (приходи з накладних) у CSV + зведений PDF. Налаштовується один раз; бухгалтер сам вантажить у BAS. Прямі API — лише на запит платного клієнта.

## 2. ПРРО й акциз
| | Checkbox | Вчасно.Каса | ДПС напряму |
|---|---|---|---|
| API | ✅ відкритий REST (Swagger, тестове середовище dev-api), авторизація логін/пароль касира + ключ ліцензії каси; є сторонні SDK | ⚠️ API є, документацію не зустріли ❓ | ❓ публічного API для ПРРО без посередника немає |
| Вартість | ⚠️ від ~249 грн/міс за касу, 30 днів безкоштовно; **є згадка про підвищення до 348 грн з 19.10.2026** 🔎 | ❓ не знайдено | — |
| Вимоги | КЕП (або печатка) каси/касира, активна ліцензія каси, реєстрація каси у ДПС | подібні | — |
| Інтеграції | ✅ відомі з Poster, Syrve/iiko (джерела — частково реклама Checkbox ⚠️) | ❓ для ресторанних POS не підтверджено | — |
**Що автоматизуємо:** відкриття/закриття фіскальної зміни, чек продажу/повернення, службове внесення/виймання, X/Z-звіт, офлайн-режим, QR/посилання чека гостю в Telegram.
**Акциз у закладі:** марка сканується при першому відкритті пляшки (розлив, коктейлі — лише раз) ⚠️; у чеку конкретна назва товару + УКТ ЗЕД + реквізити марки (не «горілка»); подарункові набори — марка кожної пляшки ✅. Syrve має «відкладене сканування» марки (замовлення не закривається без неї) ⚠️ — це еталон для нас.
**Реальні ризики:** (а) КЕП касира/власника зберігається не в нас — Checkbox має підпис у хмарі, тож ключі до ATOM не передаються; (б) оплата по картці й ПРРО мають збігатися; (в) гість не отримав чек при збої мережі → офлайн-черга; (г) закон змінюється — Мінфін оновлює порядки 2026 ⚠️.
**Рекомендація:** Checkbox як перший постачальник через адаптер (інтерфейс `fiscal.sell/refund/shift`), Вчасно.Каса — другий за запитом. Фаза 2а — чек без акцизу; фаза 2б — сканування марки (у касі й боті: паритет!). Етап 0 (до коду): відповісти на 🔎-питання нижче.

## 3. Звіти в податкову, ЄП/ЄСВ, Електронний кабінет
- **Електронний кабінет платника:** Податковий кодекс вимагає відкритий API (EDI) для обміну з системами платників ✅ (норма кодексу), але **технічної документації й прикладів не знайшли** ❓ 🔎 (шукати на tax.gov.ua / у M.E.Doc, який сам підключений). Вхід — КЕП.
- **Подання звітності:** лише з КЕП платника + сертифікований канал (M.E.Doc, Вчасно, «Приват24» тощо). ATOM **не повинен** тримати КЕП клієнтів: юридичний і security-ризик, відповідальність за помилки в декларації.
- **Оплата податків:** пряма оплата — це платіжна дія з банку клієнта (потрібен банк-API та згода). Безпечний варіант: **готові реквізити + платіжний лінк/QR** («Заплатити в застосунку банку»), без доступу до рахунку. Прямий платіж — ⛔ не робити.
- **Що реально автоматизувати:** календар платежів і звітів + розрахунок суми ЄП (3% / 5% з ПДВ-статусом) та військового збору 1% від виручки ATOM ⚠️; нагадування в Telegram за 5/1 день; лічильник ліміту доходу групи. Суми й ставки 2026: 3 група — 5% (3% з ПДВ) + ВЗ 1% ✅ огляди; ЄСВ «за себе» — мінімум від мінімальної зарплати 8 647 грн (22% = 1 902,34 грн) ✅, **чинність пільги/призупинення — 🔎 бухгалтер**.
- **Конкуренти:** Poster/Syrve не роблять податкових нагадувань ❓ — це можлива перевага ATOM «заклад не пропустить податки».

## 4. Порядок впровадження
1. **Тиждень 0:** відповіді на 🔎; обрати постачальника ПРРО; перевірити, чи ваші заклади — ФОП чи ТОВ (від цього залежить, що брати).
2. **Фаза 1 (1–2 тижні):** експорт для бухгалтера (CSV/PDF) + календар податків з нагадуванням — без КЕП.
3. **Фаза 2а (3–4 тижні):** Checkbox: зміна, чек, повернення, X/Z, офлайн-черга; каса ⇄ бот. На тестовому — dev-api Checkbox, **не бойовий**.
4. **Фаза 2б:** акцизні марки (сканування, розлив/коктейлі, набори) — до/відразу після 01.11.
5. **Фаза 3 (за потреби):** прямі BAS/M.E.Doc API, Електронний кабінет, оплата податків лінком.
Не робити: зберігати КЕП, подавати звітність від імені клієнта, платити податки з рахунку клієнта.
