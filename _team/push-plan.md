# 🔔 План: push-сповіщення в шторку (каса = додаток)

Статус: план, не розробляємо до «старт».

## 1. Як це працює
- Каса вже встановлюється як додаток (pos.webmanifest). Додаємо service worker `sw.js` + Web Push (стандарт VAPID).
- iPhone: iOS 16.4+, лише якщо каса додана «На початковий екран». Android: Chrome одразу.
- Працівник один раз натискає «🔔 Увімкнути» → підписка (endpoint) зберігається на сервері прив'язаною до працівника і ролі.
- Сервер шле push **лише коли є подія** — жодного опитування, 0 зайвих запитів від телефонів.
- Ключі VAPID — тільки `wrangler secret put`. Підписки — в БД закладу, не в коді.

## 2. Підказка встановлення (перший крок)
- Каса в браузері (не встановлена) → плашка «📲 Встановіть касу як додаток» з інструкцією під iPhone/Android.
- iPhone без встановлення: кнопка «Увімкнути сповіщення» пояснює, що спершу треба додати на екран.
- Після встановлення → плашка «🔔 Увімкніть сповіщення».

## 4. Правила, щоб не набридало
- Кожен у налаштуваннях вмикає/вимикає групи (замовлення / броні / склад / підсумок).
- **Тихі години** закладу: 🟢 не приходять уночі, 🔴 приходять завжди.
- Склеювання: кілька подій за хвилину однієї групи → одне «3 нові замовлення».
- Подію, яку вже хтось обробив (взяв замовлення) — прибираємо в інших (той самий `tag` → заміна сповіщення).
- Тільки працівникам **на зміні** (крім власника й підсумку дня). Офіціант не на зміні — нічого.
- Не дублювати свої дії: хто зробив подію, той не отримує сповіщення.

## 5. Тап по сповіщенню
- Відкриває касу одразу на потрібному: замовлення / стіл / бронь / звіт дня (`data.go` → наявний `view`/`setTab`).

## 6. Паритет з ботом
- Telegram-група лишається як є (не спамимо більше).
- В особистому боті працівника — ті самі групи налаштувань: «куди слати: 🔔 додаток / 💬 бот / обидва».
- Один спільний виклик `alert(env, {ev, to, text, go})` → сам розсилає в push і/або бот.

## 7. Технічно
- `sw.js` (у корені, scope каси): `push` → `showNotification`, `notificationclick` → відкрити/сфокусувати касу.
- `worker/src/push.js`: VAPID-підпис (WebCrypto, без бібліотек), шифрування payload (aes128gcm), `pushTo(env, filter, msg)`.
- Підписки: `push:<staffId>` → до 3 пристроїв. Відповідь 404/410 від Apple/Google → підписку видаляємо.
- Хуки: поряд з наявними `notify(...)` у pos.js / site.js / delivery.js / courier.js / kitchen.js / stock.js / digest.js — `alert()` з подією і отримувачами.
- Запити: 1 вихідний запит на пристрій на подію; нічого з телефонів.

## 8. Тестування
- `worker-test` + тестова підписка; тести: підпис VAPID, шифрування, фільтр ролі/зміни, тихі години, склеювання, видалення мертвих підписок.
- Ручна перевірка на iPhone (встановлена каса) і Android: заблокований екран, звук, тап.

## 9. Етапи
1. Підказка встановлення + `sw.js` + кнопка «Увімкнути» + тестовий push.
2. Адмін: замовлення з сайту, броні, оплати, **підсумок дня**.
3. Кур'єр і офіціант (нове замовлення, «страва готова»).
4. Кухар, склад, власник.
5. Налаштування груп, тихі години, склеювання, вибір бот/додаток.

## ✅ Рішення власника
- 🔴 — гучний звук.
- Підсумок дня — після 23:00 (як digest).
- «Страва готова» — лише офіціанту свого стола.
- Нове замовлення — усім офіціантам на зміні.
